## 1. 最优先的功能问题：随从没有真正参与战斗

在不修改 `boarding.gd` 的情况下，加载真实 `return_demo.tscn`，分别运行有／无开场压制的默认自动战斗。两次随从攻击启动次数都为零。

- 无压制：约第 2 秒移动到中央障碍附近，此后距离目标约 2.35 米；攻击范围为 1.65 米。从第 3 秒到战斗结束，逐秒净位移只有约 0.001–0.004 米。
- 有压制：开场先按现有规则停 5 秒，恢复移动后又卡在相同一带，距目标约 2.36 米。
- 单人物运动探针对 110 条抽样路线都能通过。这证明多人站位与当前运动规则组合有问题，并不证明所有单人路线都正确。
- 原 29 项检查没有覆盖多人到达攻击位置、持续无进展与随从实际参战；不能据此声称这块已经验证。

诊断文件在 `Local/ReturnDemo/critique-20261010/`：`boarding-behavior-probe.json`、`navigation-probe.json` 以及两个 `.gd` 探针。探针只运行原方法，不修改存档；无渲染的自动战斗复现不等同于重放用户完整操作。

当前人物每帧直奔目标，靠近圆障碍临时偏向一侧，再被其他人推开；没有整条路径、目标周围可达的近战站位、受阻重选路径或窄路让行。这种规则可以让单人绕开桅杆，却会让多人互相阻挡。

应先修正路径与站位，再判断头目和随从是否太弱、战斗是否过快。

## 2. 当前甲板范围到底如何规定

来源：`Godot/scripts/demo/boarding.gd`、`rules.gd`，以及 `tools/assets/inspect_demo_ship.py`。

| 数据 | 当前实现 | 限制 |
| --- | --- | --- |
| 可移动平面范围 | 敌船局部坐标 x 为 -1.95～1.95，z 为 -4.6～4.6，约 3.9×9.2 米 | 手填矩形，不是按整艘船形状生成 |
| 开场部署区 | x 为 -1.75～1.75，z 为 1.0～4.1，约 3.5×3.1 米 | 仅用于剧情规定的入场布阵 |
| 障碍 | 中央桅杆／舱口附近与前桅杆两个圆 | 未完整表达舱室、船舷、绞盘和通道形状 |
| 脚底高度 | 原船网格向下射线采样，间隔 0.15 米 | 只供脚底贴地；缺失值回退到固定高度，不会阻止寻路 |
| 友船与跳板 | 有实际可见模型 | 不在当前人物可走范围内，没有两船之间的导航连接 |

还复现了两处边界不一致：`safe_point` 先夹进矩形，再推出障碍，能把前端点从 z=-4.60 推到 -4.66；部署不检查战斗障碍，可把人放在战斗阶段会被推出的位置。这些都应统一到同一套可行走数据。

### 不同船型的正式做法

每个船型保存一个可复用场景：可见船模、贴合真实甲板的简化行走面、障碍、导航数据、部署区与上下船连接点。同船型实例复用；改船上布局才重做相应数据。

1. 统一人物视觉身高与实际占地半径。地面选中圈只是提示，不能各处另用互相矛盾的尺寸。
2. 在真实甲板上标注行走面，保留船首收窄、船尾、台阶和必要高差；把舱室、桅杆、不可踏入的舱口等标成障碍。简化的是不可见导航数据，船的可见美术保持完整。
3. 由这些干净的几何生成导航网格，按人物半径向内留余量。不要把生成模型整船每个三角形直接当可走地面；顶篷、绳索、饰物和错误小面会污染结果。
4. 部署区是可走面的一个或多个子区域，单独表示剧情限制。点击不能到达的位置应有明确反馈，不能默默把指令夹到矩形边上。
5. 台阶、跳板和多层甲板使用明确连接；跳板达到接舷条件才开放。寻路负责绕开障碍，人物避让和目标周围站位另行处理，不能只开避让就认为解决了寻路。

Godot 官方说明导航网格描述的是角色中心能够安全到达的区域，视觉模型与碰撞形状不会自动变成寻路限制；人物半径要在烘焙时计入。[Navigation meshes](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationmeshes.html)。动态避让独立于路径规划，也不自动知道完整场景障碍。[NavigationAgents](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationagents.html)。

本 Demo 的人物战斗是独立场景，接舷后可以固定两船相对位置，在船体局部空间组织战斗。无需因为航行地图中的船正在移动就每帧重烘焙甲板。未来边航行边打、动态断桥等另验，不能仅靠给导航节点换父节点来保证正确。

## 3. 镜头与人物比例

现有战斗镜头同时展示两艘完整船，人物只是画面中很小的一部分；人物又偏暗，桅杆、绳索和船舷遮挡明显。应先把战斗镜头聚焦到正在交战的甲板，尝试放大到现有约 1.25–1.4 倍，并保留战术视野切换；不对每次普攻切镜。

当前战斗精灵按旧源帧约 1.94 米可见身高标定，老梁约 1.78 米；船模包围盒长约 16 米、宽约 5.3 米。这些是工程尺寸，不是历史船型尺度结论。不能仅靠把人物放大来修补读不清，否则走道更加拥挤。先统一人体、门洞、栏杆和通道的比例，再定镜头与新动作在屏幕中的有效尺寸。

近景同时检查肤色／衣服受光、脚底接触、甲板遮挡和头部轮廓。只对真正遮住人物的前景绳索／桅杆做受控遮挡处理，保留完整船体及 v03 质感。

## 4. 人物素材应完成到什么程度

目前主角、阿棠、头目、随从复用同套旧人物，攻击只有姿态偏移、刀光／箭体；倒地是把人物平面旋转。老梁仅一张静态站姿。独立对白立绘没有完成。

先以同一人物设计参考分别生产场景精灵和对白半身立绘，保持面貌、衣服、武器和色板一致。立绘有独立构图和分辨率；场景动画保留固定画布与脚底根点。

| 角色 | 需要的主要动作 | 独立对白素材 |
| --- | --- | --- |
| 主角 | 待机、八方向移动、普通攻击、强攻、受击、倒地；防护姿态随成长技能实际需要增加 | 半身立绘，常态、警觉／思考、决意等少量表情 |
| 阿棠 | 待机、八方向移动、举弩瞄准、射击、装填／收势、压制射击、受击、倒地 | 独立半身与剧情需要的表情 |
| 头目／随从 | 可复用部分基础运动；形象与装备可辨，攻击、受击、倒地，头目另有蓄力重击 | 有对白的敌人制作对应半身，沉默随从不强增对白资产 |
| 老梁 | 待机呼吸、交谈小动作、步行／跟随、获救起身等实际出现的表演 | 独立半身，担忧、虚弱、释然等实际需要的表情 |

只有移动要求八方向；普通攻击／射击先做右向源片和左向镜像，稳定一次动作中的朝向。新角色先完成一段代表动作，检查武器变形、脚步漂移、准备—出手—恢复和正常游戏尺寸，再展开剩余素材。不要复用已关闭失败攻击，不用多镜头打斗视频冒充可操控游戏动作。

## 6. 海面与航迹为什么显得生硬

`demo_ocean.gdshader` 的可见亮带主要由少数正弦波叠加与阈值产生，固定栅格的细碎高光进一步强化重复方向。水面仍是平面；波浪主要改颜色和反射采样。港口只露少量水面，扩大为大片海域后，平行条带便成了主要视觉内容。

船首和船侧扰流用船体局部坐标的固定形状，只随速度调整强度；缺少沿船侧流动、破碎、脱离和扩散。尾迹已经记录真实运动历史，但外缘过于连续、近似等宽，容易呈现两条轨道。

建议保持 v03 色板和绘制质感，重做大海镜头下的运动层次：

- 大尺度低对比起伏、中尺度不同方向细波、少量破碎的亮面；减少整片等距长条，远处减少细节频率和闪动。
- 水面法线／反射扰动保持一致；少量几何起伏与船体轻微运动配合，不依赖模糊和高亮遮盖问题。
- 船首分水随速度和转向改变，船侧泡沫向后流、断裂并融入尾迹；停船后逐渐消散。
- 尾迹保留实际曲线路径，增加宽度、破碎和消散差异；转弯两侧强度不同，避免两条连续描边。

不要用预渲染整段海浪或航海视频替代实时水面。H3 适合提供笔触、泡沫或短特效源片；世界位置、方向、强度与时间关系由 Godot 控制。

## 7. 炮击反馈需要完整过程

当前炮弹半径 0.19 米，在海战远镜头只占少量像素；深色球和海水对比低。尾迹是半径 0.018 米、长 0.8 米的细圆柱，每段仅保留 0.1 秒，缺少有体积的运动表现。落水是 0.48 秒的单帧水花加淡出的泡沫，没有真正分段动画。

v5 自动录像记录 24 发发射、24 发命中、0 发落水。因此该回放没有覆盖落水视觉评审，不应据此认为水花已验证。

建议按完整链条制作：炮口短闪与后坐→沿炮口方向推出的烟团→可辨认的铁弹体与克制短尾迹→船体命中的木屑、烟尘和短促反馈，或落水的起水、水滴回落、残留泡沫和扩散波纹。普通弹落水仍不产生当前规则之外的伤害。

显示尺寸可以按游戏镜头适度增强，但判定半径要单独控制，不能为看清而悄悄增加命中范围。正式评审安排一次命中、一次擦过、一次明确落水，在正常速度和指挥慢速都检查实体、轨迹、声音与结果对应。

## 8. 下一轮建议顺序

1. 修甲板寻路、障碍和多人接敌站位；用同一数据校验部署与移动，并检查不同船型的复用方式。
2. 定近距战斗镜头、人物／船比例和 UI 占用空间；这样才能确定新动作与立绘需要达到的有效尺寸。
3. 本地制作一组代表素材：主角攻击、阿棠射击、老梁动作及独立半身；按真实游戏尺寸检查后补完整角色状态。
4. 制作统一 UI，并完成一段独立立绘对白与一次选中下令的实际交互。
5. 单独精修航海水体、动态船边泡沫、尾迹和炮击全过程；用直航、转向、停船、命中／擦过／落水片段评审。
6. 将通过的小样接回整段故事，再评估战斗时间、成长收益和趣味性。旧版流程能完成不等于这几项已经通过。
