# 自动即时战斗、子弹时间指挥与海上遭遇分析

日期：2026-10-10。状态：分析与方案修订，未实现玩法、未生成素材、未新增支出。

## 1. 当前方向与可行性判断

用户提出以《白荆回廊》为参考：人物和船只默认自动攻击、使用技能，点击己方单位进入很慢的子弹时间，再指定移动、目标或技能，结束指挥后恢复正常速度。

用户随后明确两种空间规则：

- **人物战斗进入专用场景**，开战前在剧情指定的一个或多个有限区域内布阵。
- **海战在当前航行海域直接发生**。敌方可以主动攻击，不重新加载一张海战地图；玩家可拉开距离，敌人放弃或追不上后解除战斗状态，继续航行。

判断：可行，也适合人物冒险与船队指挥并重的方向。两侧能共享“平时自动执行、关键时刻下令”的操作习惯；不同的移动、射程与场景规则保留各自特点。

该方向替代上一份 Demo 的人物回合制优先提案。下面的速度、AI 行为、脱战判据和技能细节是建议，仍需试玩；不能把设计分析当作实现授权，也不能由此宣称完整战斗已经定稿。

## 2. 《白荆回廊》核对范围

本次查阅公开文字机制资料，未运行游戏或声称完整观看实战。官方《知识情报局》2023-04-26 的介绍明确描述了战前调整部署、开战后自动普攻、手动战术移动及技能，以及指令冷却和技能次数限制。[官方机制介绍](https://www.taptap.cn/moment/400046169461362568)

2023-11-03 项目组前瞻还说明了环境／元素区域、关卡提示和战斗操作的调整。这里的启发是让场景与指令共同影响战局；不把其终端防守、元素体系或养成系统整套加入本项目。[项目组优化前瞻](https://www.bilibili.com/opus/859711766727229542)

这些是对应时间的官方资料，不是对 2026 年客户端每项细则的实测。没有从上述官方文字核实原作当前“点击任意人物便进入几倍慢速”的精确规则；本项目按用户提出的子弹时间方式独立设计，不冒称逐项复制原作。所有技能默认如何自动释放、指定普攻目标和海上脱战也按本项目需求设计。

## 3. 两类战斗共享什么

| 环节 | 人物战斗 | 海战 |
| --- | --- | --- |
| 开始 | 进入专用场景，按剧情布阵，确认开战 | 原海域中发现敌意、被锁定或受到攻击；直接切换战斗状态 |
| 默认行为 | 依岗位接敌、普攻、使用可自动技能 | 依作战意图操舵、维持射程与射界、自动装填开炮、使用可自动技能 |
| 玩家介入 | 点人物或头像，慢速下令移动、集火、释放或保留技能 | 点船或舰队头像，慢速下令航向、目标、弹药或船员技能 |
| 时间 | 敌我行动、投射物与冷却一起变慢；界面正常响应 | 同左；不能只有己方获得额外行动速度 |
| 结束 | 完成任务、投降、失败或剧情允许的撤离，返回探索 | 胜利、敌方投降或双方脱离追击后，继续当前海域航行 |

建议操作循环：**点击单位 → 显示慢速指挥状态 → 选择移动／目标／技能 → 确认后恢复正常速度。** 在指挥界面切换所选单位不应反复恢复又减速；取消则清除未确认的指令并恢复。后续若确有同步指挥需要，再加明确的批量指令方式，首版不强迫学习指令队列。

子弹时间先试正常速度的 5%–10%，是待调参数，不是已验证的最佳值。保留普通菜单暂停；不把子弹时间做成需要攒能量或付费的能力。指挥入口不另设资源和冷却，技能自身仍按战斗时间计算冷却及消耗。

## 4. 自动战斗必须可靠，手动干预必须有价值

默认自动攻击和技能成立的前提，是单位理解自身职责。例如近战守住前方、远程留在后方；治疗不对满血者浪费技能；船只不为攻击目标冲上岸；已经选定撤离时不为了再开一炮掉头。

玩家主要干预任务意图与时机：把技能保留给头目、移动出预告攻击区域、集中处理威胁、选择俘获而非击沉、选择脱离而非追击。自动逻辑采取合理的常规行为，不替玩家决定所有战略取舍。

### 技能怎样兼容自动与手动

- 适合自动执行的技能默认自动，可逐项切到“保留”，留给玩家手动使用。
- 点击人物开始指挥时，所选单位暂缓启动新的自动技能，防止玩家刚选中技能它就自行消耗；已发生的攻击、资源消耗和冷却仍然有效。
- 手动指定不免除射程、冷却、消耗和施放条件。确认时再验证；目标死亡或路径失效时给出反馈，不能偷偷改向另一个敌人放掉重要技能。
- 稀缺消耗品、登船和主动攻击中立目标不作为普通自动技能处理。

### 玩家指令需要持续有效

手动移动到安全位置后，人物不能立刻被普通索敌拉回危险区。建议移动目的地同时成为暂时的作战驻点，角色可在有限范围内接敌；下一条命令再改变驻点。指定集火时，目标在合理追击范围内就保持目标，不每次普攻重新选择最近的敌人。

撤离、明确移动和指定目标优先于普通自动索敌。已经进入动作承诺阶段的攻击按规则完成或被打断；普通改目标不能无限取消后摇来提高输出。首版只保留当前指令与一个明确后续动作，避免复杂队列。

首轮平衡目标：基本不干预也能维持有条理的战斗；几次恰当指令能明显减少损伤、加快解决威胁或实现不同目标。如果玩家每秒都要纠正 AI，或完全干预与完全不干预没有区别，都需要修改。

## 5. 人物战斗：剧情布阵与少量关键调度

开战前的部署区域与故事相符：接舷从登船口附近展开，正面遭遇给一块队伍区域，分路包抄可给两块小区域，遇伏时仅允许在当前落点附近调整。有限区域限制的是初始部署；开战后仍可在场景允许的通路内移动。不能借布阵把角色放到锁门后或敌人背后。

两名人物仍可用于第一轮：主角近战，阿棠远程。自动接敌时保持前后分工，头目准备有提示的重击；玩家可以点主角退到侧面，或指示阿棠使用已准备好的压制技能。恢复速度后，两人继续自动攻击。

成长也可以进入自动行为：

- **乘隙**：主角攻击到破势目标时触发一次有冷却的追击。自动战斗也能体现配合，玩家通过集火和保留技能提高成功率。
- **守望**：主角保护附近受威胁的同伴，自动满足条件时生效；玩家通过站位和指定保护对象控制覆盖范围。

生命、攻击、技艺三项基础属性仍可用于首版。实时制确实需要攻击间隔、移动速度、射程与施放时间，但它们可先作为角色／技能参数，不必全部变成需要培养的新属性。后续成长优先改变协作、职责和技能规则，再扩随机特性。

专用战斗场景也方便安排人物大小、遮挡、镜头与剧情目标。无需做站桩两排；也不沿用上一版“每人一动、打完回位、3–5 轮”的规则。

## 6. 海战：同海域交战，真正驶离后脱战

### 进入战斗不改变世界位置

敌船原本就在海域中巡行或执行任务，接近、锁定、攻击后进入战斗状态。双方位置、航向、速度、船况、弹药和装填连续保留，只切换必要的界面、提示与战斗音乐。不能收到威胁后弹出必须确认的对战菜单，也不能重新摆两排船。

航行时沿玩家航向行驶；遭袭默认允许还击，但不能为了自动接敌擅自放弃航线。玩家决定迎战后，船只按当前战术目标自动调整距离与炮口；玩家指定航向或撤离，则由该指令覆盖自动攻击机动。

船只需要转弯空间、加减速和舷侧射界；移动指令是可行航线，不是侧移或瞬间转向。首版允许简化风帆物理，但要保留船的运动特征。选船时显示预计航迹和当前射界，让玩家知道命令将如何执行。

切换弹药建议作用于下一轮装填，并明确提示；已装好的炮弹及正在飞行的炮弹不凭空改变。先用“针对船体／压制人员”两种游戏效果，不先确定未经考据的历史弹种名称。自动开炮和主动技能共用真实装填状态，不能各算一套免费火力。

### 范围是追击与脱战规则

推荐状态顺序：**航行 → 警戒／交战 → 追逃 → 脱离 → 航行。** 它们发生在同一海域，不是五张场景。

不建议用“离交战原点一个圆就立刻结束”作为唯一规则：此时敌人可能仍在近处开炮。可以给敌人合理的警戒活动区和追击上限，同时以实际威胁判断脱战：

1. 敌人失去射程后可以继续追一段；脱战距离比触发交战的距离更大，避免边缘来回切状态。
2. 玩家拉开距离并维持一小段时间，敌人无法重新建立攻击，或已到追击上限／选择放弃，逐步停止追击、返回巡行。
3. 所有仍相关的敌方威胁都解除后才结束战斗；不能只因离其中一艘远了就判安全。首版单船对单船，后续船队还需检查落后船只。
4. 尚可能命中的在途炮弹继续正常结算，不能通过跨过范围线使其消失或获得免伤。

脱战确认时长可先试约 6–10 秒战斗时间；具体距离需结合镜头比例、船速、射程和一次转向的时间确定，当前不编造世界米数。进入子弹时间时脱战计时同步放慢，不能在慢速菜单里等真实秒数获得脱战。

敌船不追到整片世界，也不在边界瞬间隐身或回满血。脱战保留双方实际船况、已消耗弹药和技能状态；同一敌人再交战仍是原来的对象。未完成目标不发胜利奖励，同一目标的奖励只结算一次，避免反复出入范围刷资源。

“撤离”命令应让己方优先沿撤离方向航行，停止主动追击和为争取射界而掉头；若敌船更快或我方严重受损，仍可能逃不掉。是否交战与如何逃走才有意义。

### 接舷与独立人物场景兼容

海战逼停、接近、确认登船后，可以进入专用甲板战斗场景，这与用户指定的人物战斗结构一致。海战状态转成甲板条件，例如压制让一名守卫开场短时间反应迟缓，而不再使用“首轮不能行动”的回合表述。

首版只有两船，接舷时保存双方位置与船况，人物战结束再回到相同海域状态。是否让远处其他舰船继续实时炮战，是未来多船版本的独立问题，不在本次暗中增加第二条战斗模拟。

## 7. 实现可行性与主要代价

Godot 提供 `Engine.time_scale`，可影响依赖游戏时间的更新和计时器；音频速度需要另行处理。计时器也能选择忽略游戏时间缩放。技术上具备慢速指挥的基础，但每个战斗系统仍需要正确使用时间。[Engine 官方文档](https://docs.godotengine.org/en/stable/classes/class_engine.html)、[Timer 官方文档](https://docs.godotengine.org/en/stable/classes/class_timer.html)

建议拆成两层：共用的选择／指令／时间／目标／技能状态，以及人物、船只各自的运动与自动行为。人物寻路不能直接当船只操舵；共享玩家操作也不等于两个战斗控制器完全相同。

| 主要工作 | 必须解决的具体问题 |
| --- | --- |
| 自动行为与指令优先级 | 不乱追、不浪费技能、不覆盖玩家刚下的命令；目标失效时可解释 |
| 人物走位与接敌 | 桅杆／箱体不堵死，近战有可用攻击位置，远程不撞进前线 |
| 船只操舵与炮组 | 转向半径、航迹、射界、装填、避碰；撤离不能变成绕圈开炮 |
| 同海域遭遇状态 | 连续进出战斗、有限追击、在途攻击、资源保留、重复进入和任务奖励 |
| 时间一致性 | 动画、伤害、冷却、炮弹、AI 与脱战计时一起缩放；界面、鼠标和指挥镜头正常响应 |
| 清楚的画面反馈 | 同时行动仍能看清人物和目标；普通攻击不过度抢镜；慢速、暂停和剧情演出不相互覆盖 |

这会降低玩家的连续操作负担，但仍需要完整的实时战斗逻辑和较可靠的 AI。相比纯手动动作战，可减少连招、精确闪避和复杂输入判定的范围；相比上一版简化回合制，自动走位、实时技能协调和海上追逃明显增加工作。

当前 `Godot/` 仍是港口视觉样片，已有移动与动画、水和船体摆动；没有上述战斗系统。现有画面和素材生产线可继续使用，不能把加一个时间倍率误报为完成了战斗。

## 8. 对 MiniMax、美术与效果的影响

主要素材分工不变：MiniMax 做人物动作，三维模型提供船／甲板／障碍空间，Godot 做指令、伤害、弹道和效果。

但需要提前验证两件事：

- **任意接敌位置与左右攻击素材**：八方向移动仍有效；攻击继续先试右向源和左向镜像，面向相机判断左右并锁定一次出手方向。目标在正前后、多人围攻和甲板遮挡时是否可读，需要实际检查；不能靠瞬移排成横排，或偷偷增加八向攻击任务。
- **慢速下的逐帧动画**：低倍率会让单帧停留更久，容易暴露姿态跳变、脚滑和刀具变形。提高运行帧率不会自动产生缺失姿态。要用代表动作测试 1 倍与子弹时间，必要时调整动作节奏、镜头和慢速倍率，再决定素材改进。

自动战斗多人连续出手，不适合每次普攻都做全局顿帧和大幅震屏。普通攻击主要用局部受击、声音和克制的特效，关键技能才给明显强调；已有子弹时间与命中强调要统一管理，不相互把时间倍率改回正常。

## 9. Demo 应怎样改

保留《归港的人》剧情和港口、近海、甲板三个场景的范围，改变战斗规则：

1. 先在一张很小的专用甲板场景验证两名我方、两名敌方：有限区布阵、自动攻击与技能、点击慢速、移动／集火／技能干预、取消恢复。
2. 在一个海域验证一对一遭遇：正常航行、敌方主动攻击、原地进入战斗、自动舷炮与下令、成功甩开／没能甩开、脱战继续航行。返回再交战，核对状态没有刷新。
3. 接通海战逼停与甲板救人，保留压制结果；再恢复招募、一次改装、一次人物成长和归港收尾。

每个小验证都应很早加入一条有质量的攻击和声音，不能用无声占位体宣布战斗爽感成立。新素材仍按代表样本逐个检查，不因变为实时制就扩整套人物或舰队。

首版不加指挥能量条、复杂脚本编辑器、完整元素反应、多船编队或随机系统。先观察：不下令时是否可靠，少量下令是否有效，大部分时间能否正常速度观看战斗，海上是否真的能够交战与脱离。如果需要一直慢速纠正 AI，则自动行为、敌方预告或决策密度需要重做。

本次只研究并更新规划。v03 运行画面、MiniMax Library、已有船任务与腾讯费用台账保持不变。
