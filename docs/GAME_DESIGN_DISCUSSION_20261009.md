# 航海 RPG · 核心玩法与世界观讨论稿

日期：2026-10-09。状态：设计讨论，未授权据此直接展开完整游戏实现。

后续用户要求先规划一段更简单的固定短故事，当前具体提案见 [Demo 剧情、玩法与素材方案](DEMO_STORY_AND_PRODUCTION_PLAN_20261009.md)。下文保留为全作方向与可选方案，不把多船规模、复杂传递状态或额外陆地任务自动加入本次 Demo。

2026-10-10 更新：用户提出以《白荆回廊》为参考的自动即时战斗与子弹时间指挥，并明确人物专用战斗场景、海战同海域遭遇及脱战。最新分析见 [战斗方向修订](COMBAT_AUTOMATION_AND_ENCOUNTERS_20261010.md)，下文 A/B 回合制比较不再是当前优先方案。

## 1. 已确认与尚未定案

用户已确认：

- 港口 v03 **基本满足美术风格验证，整体感觉已经对味**；细节可继续优化。
- 航行、海战及相应镜头／水面／特效另行验证，港口认可不自动覆盖海上全部表现。
- 游戏是 RPG，包含 NPC 对话、对话框、场景演出与剧情推进。
- **人物冒险与船队经营大致均衡**，两侧均应有实质决策。
- 首作从明朝出发，包含远洋与欧洲。欧洲不能仅作为后续作品或片尾地点。

仍未确认：陆战、海战、接舷的具体形式；主角、年份、架空分歧、超自然程度、主线剧情、人数与船队规模、养成细则、额外模式。

以下模式、数量、故事和优先级都是建议，不能由后续实现者当作用户定案。现有沈砚只是验证素材；穿越仍是可选项。本次仅更新规划与认可状态，没有修改 Godot 玩法、提交素材任务或新增支出。

## 2. 建议的整体定位

**玩家扮演一位亲自带同伴冒险、同时统筹远洋船队的主角。人物决定能怎样处理事件，船与船队决定能抵达哪里、承担什么任务以及怎样面对海上风险。**

一次完整循环可以是：

港口调查／对话 → 接受或自行选择目标 → 配队、配船、装货与补给 → 航行与遭遇 → 陆地任务或海战 → 结算、修理与同伴互动 → 港口关系和新航线变化。

均衡体现为每一章都有两侧的重要选择，不要求每段剧情的时长严格各占一半。贸易、护航和探索应能推进人物与主线；陆地获得的人脉、情报和技术也应改变船队的选择。

船还应是可进入的共同生活空间。对话、休整、同伴关系、任务回顾和部分制作可在船上发生，使长途旅行仍有人物内容。

## 3. 战斗先比较完整组合

| 组合 | 人物陆战／接舷 | 海战 | 适合的体验 | 主要代价 |
| --- | --- | --- | --- | --- |
| A · 建议优先验证 | 小规模队伍回合制，保留适量站位与掩体／通路决策 | 连续航行，可暂停下令；主要控制旗舰，伴航船执行职责 | 人物配队与船长指挥都突出，海上保留转向和接近的感觉 | 两种节奏的衔接；舰船寻路、编队与指令反馈仍需认真制作 |
| B · 同样值得比较 | 小规模队伍回合制 | 舰船回合制／分阶段下令，移动与炮击通过短演出结算 | 统一的策略节奏，便于思考、读状态与比较方案 | 海战可能偏棋局；航行的连续感需由探索层补足 |
| C · 暂不优先 | 人物即时队伍战或动作战 | 即时海战 | 强操作与临场感 | 动画、打击反馈、队友 AI、寻路与多单位控制的综合成本最高 |

这些是针对本项目的设计判断，不是精确工期评估。即时可暂停也需要完整实时系统，不能当作无需 AI 的便宜折中。现有八方向移动可继续使用，最终战斗动画仍应另做小样，不能只为了迁就现有素材决定玩法。

### 人物战斗的规模

先验证少量角色、短场地和清楚目标。回合制不必等同于很大的战棋地图；也不必预先锁成两排站桩。可以比较有限走位、区域站位两种表现，考察：

- 保护目标、抢占通路、打断与协作是否有趣。
- 同伴个性与战斗定位能否被记住。
- 普通遭遇是否过长，能否及时回到探索和剧情。
- 甲板、仓库与街道能否复用同一套人物规则。

### 海战的核心决策

海上首先让航向、射界、距离、装填时机和护航目标有意义。初版可用炮组指令和可读的射界提示，不要求逐门炮瞄准。伴航船可以接受护卫、压制、集中攻击、撤离等少量明确任务。

原型可从一艘旗舰、两艘不同职责的伴航船起步，用来检验指挥负担；这不是成品数量承诺。不能先扩成大量舰船逐一操作，再设法补界面。

## 4. 接舷复用人物战斗，并继承海战结果

接舷是海上遭遇的一种解决办法。炮击取胜、逼退、撤离或对方投降，也应能结束冲突。不能让每一场海战都强制再打一场清场战。

建议海战向接舷传递少量可读状态：

| 海战状态 | 接舷中的后果示例 |
| --- | --- |
| 船体与甲板损伤 | 个别通路受阻、火点或危险区域 |
| 人手与士气受压制 | 对方少量增援延后、投降阈值变化 |
| 接近方向与先手条件 | 不同登船点和初始站位 |
| 我方核心人物的伤势与准备 | 可出战人数、补给与战术选择 |
| 当前任务目标 | 救人、夺取文件、控制船长、保护货舱等不同胜利条件 |

所有传递结果都应在接舷前清楚提示。转换时保留已经付出的代价，不能把双方状态重置成满血。

第一版可用清楚的镜头／场景过渡进入甲板战，先验证规则和后果。持续摇晃的甲板物理、几十人同屏混战、无缝切换不是这一步的必要条件。

## 5. 人物、船和船队都成长，各自承担不同职责

| 层次 | 值得培养的内容 | 给玩家带来的变化 |
| --- | --- | --- |
| 主角与核心同伴 | 战斗技能、装备、专长、个人剧情和关键关系 | 更丰富的陆战、对话与事件处理方法 |
| 关键船员岗位 | 舰长、领航、炮术、修理、医务、交涉等功能 | 航行、战斗与经营中的不同优势 |
| 船只 | 船型与固定模块改装、功能舱位、维护状态 | 航程、载货、机动、火力与保障能力之间的取舍 |
| 船队 | 舰船职责组合、舰长任命、资金与港口关系 | 能承接的任务、可利用的补给点与航路选择 |

核心同伴可以有一个人物战斗定位和一个航海／经营专长。例如火器手影响接舷与炮组，医师影响战斗恢复与航后伤病，交涉者影响对话与贸易条件。这些是游戏功能位，不是明代船队官制的事实说明。

纯文职角色不必强行变成武林高手。普通船员可先用人手、训练与士气的编制表示，不为每个人建立独立装备、技能树和完整对白。普通人手保证船的基础运作，具名同伴提供特色选择；同一人同一时刻只占一个关键岗位。

船的成长主要通过船型与配置体现，不必再复制一条人物式经验等级。换船时应允许合理转移船员和部分投入，保留玩家对长期船队的认同。

### 改装与炮弹怎样控制复杂度

先从四类固定改装位置验证：船体、帆装、炮组、功能舱。每类选项要有代价，例如：

- 更重的火力占用载货和机动余量。
- 更大的货运配置降低战斗保障或续航冗余。
- 医务／维修设施帮助长航程与伤后恢复，但占用其他功能位置。

以上是拟议的游戏平衡，不是特定船型的历史参数。先不做自由拼船、任意摆炮与完整浮力工程模拟。

弹药可先分为“针对船体”“削弱机动”“压制船员”三种战术效果，具体弹种名称待年代与国内史料确定后再采用。常规弹药并入补给管理，特殊弹药保留有限库存，避免每次出航都清点多种口径、引信与零件。

改装菜单本身不算最难。真正扩大范围的是每种配置对应的船模表现、射界、AI、平衡，以及它与接舷和剧情状态的联动。

## 6. 航行要有选择，也要控制空白时间

建议将远程航路、区域航行与遭遇镜头分层：

- 远程航路负责目的地、路线、时间、给养和风险选择。
- 区域航行负责发现、接近、风向／天气变化与事件。
- 战斗镜头突出船型、航向、射界和炮击结果；接舷后再切到人物尺度。

航行中要有可判断的风险和机会，不能主要由长时间按住前进组成。贸易、救援、航道调查、特殊海况与同伴事件可成为不同类型的遭遇。

港口自由对话和剧情演出不宜持续暗扣给养或偷偷触发逾期。可先让出航、执行委托、休整等明确行动推进日程；有时限的任务明确显示规则。这样玩家能放心阅读 RPG 内容，同时在经营决策时认真考虑时间。

海上美术另做一份很小的验证：两三艘不同职责船同屏、转向和交错、炮击及命中、接近登船和危险海况。重点检查可读性与操控判断，不能仅换一个漂亮水面。

## 7. 剧情与世界观的建议

先定四个支点，再写完整年表：

1. **时代与技术边界**：大致年代、船与火器水平、信息传播方式。
2. **架空分歧**：改变了什么，影响到哪些组织、利益和航路。
3. **主角的资格与动机**：为什么能统筹船队，又为什么必须亲自上岸处理事情。
4. **超自然程度**：写实、民俗神秘，或明确奇幻。它会改变人物职业、敌人和海上危险。

穿越不作默认前提。真实历史主张与原创设定分开，欧洲同样按 [历史来源规范](HISTORICAL_SOURCE_POLICY.md) 考据；其他游戏的时代介绍和地图不作史料。

### 一个可讨论的原创开局

**一支被认定失踪的远航船队，竟在失联后继续签发新的货单。主角受托接手残存的船、人和债务，沿着货物与消息的去向追查。**

这只是故事提案。它可以同时提供：

- 个人动机：寻找与自己有关的人，弄清一段被隐瞒的经历。
- 经营动机：修复船队信用、筹措远航资金、重新建立沿途关系。
- 世界冲突：不同组织争夺航路、契约与信息，主角需要选择合作与代价。

主线可采用“章节目标＋区域自由”。从大明出发建立船队，经沿途港口逐步揭开更大的冲突，欧洲安排为真正可玩的重要篇章：有当地人物、冲突、同伴和能影响结局的选择。不能抵达欧洲就结束。

结局可以关心带回了什么、守住了谁、建立或失去了哪些关系。支线则补充同伴、地方生活与选择后果；不必让每个普通对白都分出一条独立主线。

## 8. 额外玩法的优先级

| 优先级 | 内容 | 与两条主循环的联系 |
| --- | --- | --- |
| 优先 | 同伴个人事件与船上生活 | 让人物成长、关系、岗位与远航记忆结合 |
| 优先 | 贸易委托、护航与悬赏 | 为配船、资金、货舱与战斗方式提供不同目标 |
| 优先 | 航道／遗迹／沉船探索 | 带来情报、航线、技术线索和剧情，不只是捡钱 |
| 后续候选 | 少量港口据点与商路经营 | 提供补给、人脉和有限持续收益，暂不扩成殖民地建设 |
| 之后再评估 | 航线挑战、独立战斗挑战或硬核航程 | 复用已经好玩的系统，再形成额外模式 |

钓鱼、种田、烹饪、自由造船、全面市场模拟等不是一起加的清单。只有能明显服务人物或船队的项目才进入近期范围。

## 9. 还需要提早考虑的几件事

- **损失与失败**：普通模式先考虑撤退、修理、部分货损和伤势；核心同伴永久死亡会显著增加剧情分支与补救成本，需单独选择。
- **任务解决方式**：谈判、护送、调查、破坏与战斗应有合理分工，不把所有职业最终都做成加伤害。
- **内容覆盖方式**：关键港口做完整可探索场景，其余补给点用事件／菜单组织；首作的欧洲篇章仍是实质内容。
- **经济节奏**：人物装备、船只升级和补给共用可理解的资金关系，避免同时出现大量互不相通的成长货币与重复刷取。
- **同伴分工与队伍规模**：先小规模验证登陆队和伴航舰长的选择，再确定具名角色数量，不先承诺大阵容。
- **演出产能**：对白、任务状态、人物表情和少量关键场景优先；全配音与大量独有动作需另行估算。
- **存档与世界状态**：航前准备、重要选择、海战结果及接舷状态需要一致保存；读取后不能把已消耗资源或伤势重置。

## 10. 下一步建议的验证任务

先设计一段约 15–20 分钟的体验目标，而非立即开发完整主线：

1. 港口里接到一份与失联船队有关的护送委托，对话影响目标与回报。
2. 在船上选同伴与舰长，选择重火力护航或保留更多货运能力。
3. 出航遭遇拦截，可绕行、炮击、逼退，或选择登船取得活口／文件。
4. 海战的压制和损伤影响接舷；接舷采用与陆战相同的角色规则。
5. 抵达后通过一段上岸任务与对话改变港口关系，并回到修理、培养和下一次备航。

用同一遭遇比较 A、B 两种战斗节奏，再选具体实现。对话、任务、存档和简单演出可作为后续 RPG 基础，但本讨论稿本身不触发代码、素材或收费制作。

## 11. 参考作品与阅读范围

本次只核对官方／开发者商店页的系统介绍，未运行这些游戏，也不据宣传判断完整制作成本。

- [Pillars of Eternity II: Deadfire 官方介绍](https://eternity.obsidian.net/game)：船同时承担探索工具、共同基地、船员组织与升级载体的职责，可参考其关系结构。
- [Horizon’s Gate 开发者商店页](https://store.steampowered.com/app/1224290/Horizons_Gate/)：陆海战术战斗、船员职业成长与舰队选择可以共同组成航海 RPG，适合对照方案 B。
- [风帆纪元官方商店页](https://store.steampowered.com/app/2161440/Sailing_Era/?l=schinese)：港口交易、伙伴分工、船舱改装与舰长任命形成联动，可参考经营与人物之间的接口。

这些来源用于玩法研究，不复制规模、内容、素材或历史断言。本项目建议及取舍由本文提出，仍待用户讨论。
