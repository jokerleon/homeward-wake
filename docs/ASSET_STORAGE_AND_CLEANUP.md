## 分层保存

### 第一层：Git 工作树

只放以下内容：

- `Godot/` 的运行场景、脚本、shader、测试和最终选用资源。
- `docs/` 中的设计、技术记录和设定。
- `tools/` 中的可复现脚本。
- 小型文本清单、校验记录和版本说明。

不建议把以下内容加入 Git：

- `Assets/` 原始素材库。
- `Artifacts/` 截图、录屏和评审页。
- `Godot/.godot/` 缓存。
- 任何 API 凭据、任务回执中的敏感值、临时下载文件。

### 第二层：本机热素材库

`Assets/` 是制作现场，保留：

- 已接受的原始图和视频。
- 被用户明确否定的版本及其原因。
- 生成输入、处理配方、任务 ID 和费用记录。
- 可重新导出运行包所需的源文件。

原始素材不得只保留一份。至少应有一份独立冷备份；有条件时采用本机、外置盘/NAS、离线盘三份保存，并定期校验。

### 第三层：冷归档

阶段验收后，把不再频繁打开但仍有历史价值的目录打包到外置盘或 NAS。归档包必须带：

- 版本名和日期。
- 文件清单与大小。
- 来源和用途说明。
- 是否含被否定素材。
- 对应的 Git 提交或标签。

## 目录规则

- `Assets/Characters/Library/`：已接受或稳定复用的角色资源。
- `Assets/Characters/Working/`：制作中、候选和被否定版本；保留来源，不做无记录覆盖。
- `Assets/Characters/Trials/`：离线试验，不得直接当作运行资产。
- `Assets/Characters/Recipes/`：处理配方与可复现步骤。
- `Assets/HarborTrial/`：港口、场景、模型和贴图试验。
- `Godot/assets/`：只放运行真正加载的副本；不要把它当第二套源素材库。

新增素材时，优先在对应 `Working/<角色>/<动作-版本>/` 下保存原图、处理包、提示词、任务记录和评审状态。文件名不得只有日期或 `final`，必须能看出对象、动作、方向和版本。

## 素材清单

每次大清理、版本归档或磁盘迁移前，先生成清单：

```powershell
./tools/assets/inventory_assets.ps1 -Roots Assets,Artifacts
```

清单默认写入 `Artifacts/asset-inventory/`，包括相对路径、字节数、扩展名和最后修改时间。该目录不进入 Git，但应随阶段归档一起备份。

清单用于判断：

- 哪些文件仍被 `Godot/` 运行资产引用。
- 哪些目录只有预览、临时导出或重复中间包。
- 哪些候选版本缺少说明，不能贸然删除。
- 哪些旧评审产物可以整体移出工作盘。

## 清理候选

以下只是候选，不代表已经批准删除：

| 候选 | 体量/位置 | 判断 |
| --- | --- | --- |
| Godot 导入缓存 | `Godot/.godot/`，约 165 MB | 可再生成，已忽略；需要时可重建，不建议作为版本交付物 |
| 旧评审视频与截图 | `Artifacts/`，约 887 MB | 完成阶段结论后可整体冷归档；先保留引用它的报告 |
| 已否定的港口试验 | `Assets/HarborTrial/v02/` | 是历史证据，不直接删除；可冷归档 |
| 角色动作预览 GIF | 多个 `pack*/previews/` | 体积大、可重新生成；需确认对应评审记录后处理 |
| 重复的 `pack-runtime-vXX` | `Assets/Characters/Working/*` | 可能是不同验收阶段来源，不能仅因名称相似删除 |
| `.blend1`、临时下载、失败分包 | 分散 | 可先扫描并列入隔离区，不应直接永久删除 |
| `__pycache__` | 工具目录 | 可再生成，适合清理 |

严禁在没有清单和确认的情况下删除：

- 用户接受或明确否定的原图、原视频。
- 生成输入、处理配方、任务 ID、费用记录。
- 被当前 `Godot/` 引用但看似重复的文件。
- 任何 `Library/`、`Recipes/`、`References/` 中的来源材料。

## 隔离而不是立即删除

需要清理时采用三步：

1. 生成清单并把候选移动到 `Assets/_quarantine/<日期>/`，保留原相对路径。
2. 保持隔离区至少一个开发周期，运行 Godot 检查、关键场景截图和必要回归。
3. 确认无引用、已有冷备份且用户同意后，再永久删除。

`Assets/` 整体已被 `.gitignore` 排除，因此隔离区不会污染 Git；但隔离目录仍应写一份 `README.md` 说明来源、候选理由和删除日期。

## 同步与交接

- 代码、文档和工具的变更正常提交并推送。
- 素材交接优先写文件清单，不通过聊天反复发送大文件。
- 需要让其他机器复现运行时，只打包 `Godot/` 实际引用资源加清单，不打包整个 `Assets/`。
- 需要外部协作时，使用网盘、对象存储或专用素材库；不要让 Git 仓库承担 5 GB 以上的原始生成库。
- 大文件若确需进入 Git LFS，先核对是否运行必需、是否有授权、是否有更合适的归档位置。
