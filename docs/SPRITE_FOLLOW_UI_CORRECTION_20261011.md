# 场景人物、跟随与游戏 UI 纠正

用户本轮明确否定船主／阿棠当前场景精灵的画风，指定旧沈砚为风格基准；同时要求查清跟随抽搐和起步／循环／停步规则，并统一九宫格与内容安全区。对白立绘身份基准不因本轮场景精灵重做而覆盖。

## 已复现的原因

- 旧跟随每帧判断距离是否大于1.7米：大于时以2.8米/秒追赶，否则立即停下。船主速度2.2米/秒，因此在距离边界反复走停。九秒“两次行走、两次停下”夹具实际记录52次起步和52次收步。
- `pawn.gd` 会把每次真假切换送入 `move_start`／`move_stop`，重复起步并非视频里绘制了52次动作。转向还会重置新方向动画帧，使细微方向变化增加跳动。
- 旧沈砚E向素材本身有32帧起步、41帧循环、28帧收步；源配方的循环退出点为23，最多等40帧。但v03 Godot实际只直接切换 `move_loop`／`idle`，没有验证那套完整起停时序。不能把源文件存在或早期预览等同于现有实机状态机正确。
- 新场景源图采用偏修长的动漫立绘比例、较亮而平滑的色面，与沈砚紧凑成人比例和低分辨率绘制方式不一致。Demo材质还从v03的0.10自发光改成了0.48，削弱了场景光照贡献。
- 旧UI把边框、文字、头像和血条分别定位，且多类边框共用估算切片边距；字体最小尺寸、头像实际比例和边框角饰没有共同约束。

## 行走和跟随规则

1. 世界位置由输入／跟随系统驱动，起步和收步片段不阻塞位置响应。
2. 一次真实行走对应：起步播放一次 → 循环持续播放 → 真正停止时收步一次 → 待机。循环不能因每帧下令或目标坐标变化而重播起步。
3. 跟随有滞回：超过2.0米开始追随；船主停止且进入1.4米以内时收步。接近目标间距1.65米时匹配船主速度，加速有上限，避免恒定快速追赶后突然停住的锯齿运动。
4. 转向只换视图，保留当前阶段的归一化帧进度；方向扇区有5度重叠区，防止边界来回跳。攻击承诺期仍锁定射击方向。
5. 所有帧共用首次脚底根点；不逐帧按包围盒或最低脚底重新居中。循环切点由源动作的姿势／脚步周期选取；数值相似度仅作候选提示。
6. 不照搬旧素材最多等待40帧的输入延迟；停止位置立即生效，收步只影响身体动作。

当前自动夹具修正后为2次起步、2次收步，包含最终静止；源记录在 `Local/ReturnDemo/follow-baseline.json` 与 `follow-fixed.json`。`Godot/scripts/demo/locomotion.gd` 是船主和跟随者共用的阶段控制器。

## 世界精灵基准

- 旧沈砚的紧凑成人比例、细暗轮廓、有限绘制细节、克制明暗和彩度；保留船主海军蓝／赭黄及阿棠蓝灰／锈赭的身份差异。
- 这是世界精灵风格重做，不能把对白立绘直接缩小当作合格世界精灵，也不把阿棠换成沈砚男性身份。
- 材质恢复v03光照响应：albedo正常接光，emission为0.10，nearest采样和明确画面像素尺度。
- 新源图出现远离人物的极低透明度噪点。尺寸测量使用与渲染裁切一致的透明度阈值，H3预备图仅按记录阈值裁外围空白，不改画人物。
- 同场景等人物高度的有效比较在 `Artifacts/ReturnDemo/style-reset-20261011-v2/`。v1的尺寸比较受上述透明度噪点影响，保留为诊断，不作美术结论。
- 右向动作仍由本地H3生成，imagegen只制作源图。所有原片、生成回执、被拒素材和处理配方保留；不把生成完成当作用户美术验收。

## 九宫格与内容规则

以1600×900为逻辑布局基准，屏幕边缘使用锚点。HUD不随某张背景图的原始尺寸随意放大；所有面板由内容容器管理。

| 背景类别 | 源像素切线：左/上/右/下 | 固定美术缩放 | 逻辑内容内边距：左/上/右/下 |
| --- | --- | --- | --- |
| 白纸对白 | 104/66/100/64 | 0.45 | 48/32/48/32 |
| 深色面板 | 76/60/76/60 | 0.50 | 32/24/32/24 |
| 头像框 | 48/48/48/48 | 0.50 | 14/14/14/14 |
| 状态条框 | 85/28/85/28 | 0.20 | 9/5/9/5 |
| 按钮 | 68/54/68/54 | 0.42 | 28/12/28/12 |

切线和内容边距是两份不同的数据，统一定义于 `ui_art.gd/FRAME_RULES`。角饰不拉伸，边缘沿单轴拉伸，中心填充。图标专用按钮使用12像素左右内容边距，不套用带文字按钮的28像素边距。

- 对白名字、正文、选项纵向排布，人物立绘有独立预留宽度；旁白时收回该预留。按钮内容处于纸框中间安全区。
- 头像卡内为头像／名字两行；生命条、冷却条和状态在框外独立排列，不能压住金角。头像保持比例，状态条外框九宫格，只有内部填充随数值变化。
- 人物／舰船指挥共用内容行规则，按钮有一致高度、间隔和内边距。
- 暂停／对白隐藏状态条的外框与全部填充，不能因更新血量重新显示孤立填充。
- 初次三尺寸八状态检查为758项，无越界／容器重叠；这是布局约束检查，不代替GPU整屏和实际点击验证。首轮整屏证据在 `ui-rules-20261011-v1`，后续修正须使用新证据目录。

2026-10-12收尾：固定24像素按钮图标参与最小尺寸计算，避免 `expand_icon` 将长选项的图标挤没；图标与文字共同占用内安全区。指挥面板按真实内容宽高收缩，并与底部提示保留间隔。最终809项布局约束通过，整屏及状态表在 `Artifacts/ReturnDemo/ui-final-20261012`。

## 船主正面步态的后续纠正

用户指出S方向仍是双腿左右开合。该视频已拒用。新源图把双脚放回髋部下方、脚尖向前；H3明确用两条平行轨迹、前脚纵深落地和后脚回收交替表现行走。新 `explore-move-S-style-v03` 已替换运行中的S，其他16张方向图集逐一SHA256不变。实际向下输入录像在 `Artifacts/ReturnDemo/front-walk-final-20261012`，该次行走只有一次起步／收步。不能把后台生成成功当成步态正确，仍以原速录像和实际脚部表现为准。

新探索素材默认使用v03光照响应；未完成替换的旧战斗占位素材保持上一版补光，以免桅杆阴影下全黑。该兼容保留不表示新战斗素材已经完成。
